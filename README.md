# پنل ارسال روبیکا (اکانت شخصی)

این پروژه معادل «پنل ارسال تلگرام» است، فقط برای پیام‌رسان **روبیکا** و با پشتهٔ **Python (Flask)**
به‌جای Node.js — چون تنها کتابخانهٔ در دسترس برای اتصال به حساب شخصی روبیکا (`rubpy`) فقط
با پایتون کار می‌کند.

## ⚠️ هشدار مهم دربارهٔ ریسک

روبیکا برخلاف تلگرام، هیچ API رسمی برای «حساب شخصی» ندارد (فقط API ربات دارد که برای
این کار مناسب نیست). این پنل از یک کتابخانهٔ **غیررسمی و ریورس-انجینیرشده** به نام
`rubpy` استفاده می‌کند. این یعنی:

- ممکن است روبیکا در آینده پروتکل داخلی‌اش را تغییر دهد و این پنل از کار بیفتد.
- استفادهٔ سنگین/پرحجم از این روش می‌تواند باعث محدود یا مسدود شدن حساب شود.

به همین دلیل، طبق تصمیمی که گرفتیم، این پنل به‌طور پیش‌فرض **محتاط‌تر از پنل تلگرام**
عمل می‌کند (تأخیر بیشتر بین پیام‌ها + سقف تعداد پیام در دقیقه/ساعت + سقف تعداد
مخاطب جدید در روز). پیشنهاد می‌شود:
- فقط برای مخاطبانی استفاده شود که ارسال پیام از تو را می‌پذیرند.
- تعداد ارسال روزانه را در حد معقول نگه داری (مثلاً چند ده تا صد پیام، نه هزاران پیام یک‌جا).

## ویژگی‌ها (کاملاً هم‌تراز با پنل تلگرام)

- ورود با شمارهٔ شخصی روبیکا (بدون نیاز به ربات)
- وارد کردن شماره‌ها از فایل Excel/CSV (نرمال‌سازی خودکار اعداد فارسی/عربی و پیشوند `00`/`0`)
- ارسال متن + عکس (کپشن)
- متن طولانی هرگز بریده نمی‌شود: اگر متن از سقف کپشن عکس بیشتر باشد، عکس بدون کپشن
  فرستاده می‌شود و بلافاصله بعد از آن، کل متن کامل به‌صورت پیام(های) جداگانه ارسال می‌شود.
- ارسال گروهی با تأخیر قابل‌تنظیم بین پیام‌ها (حداقل تأخیر و سقف‌های ایمنی از سمت سرور اعمال می‌شود)
- ادامهٔ ارسال از همان‌جایی که متوقف شده (server-side resume) — روی هر دستگاهی که پنل را باز کنی
- گزارش خروجی Excel از نتیجهٔ ارسال به هر شماره
- تمام اطلاعات (لیست شماره‌ها، متن، عکس، وضعیت) روی خودِ سرور ذخیره می‌شود، نه روی مرورگر

## تفاوت فنی مهم با روبیکا (که در پشت صحنه مدیریت می‌شود)

روبیکا برخلاف تلگرام، اجازهٔ ارسال مستقیم پیام به یک «شمارهٔ تلفن» را نمی‌دهد.
پیش از ارسال به هر شماره، پنل به‌صورت خودکار:
1. آن شماره را به مخاطبین حساب روبیکای تو اضافه می‌کند (`add_address_book`)
2. شناسهٔ داخلی (`GUID`) آن مخاطب را می‌گیرد
3. پیام را با استفاده از همان GUID ارسال می‌کند

این مراحل کاملاً خودکار است و نیازی به کار دستی از سمت تو ندارد؛ فقط دلیل اینکه
ارسال گروهی در روبیکا کمی کندتر از تلگرام است همین مرحلهٔ اضافه است.

## پیش‌نیازها

- Python نسخهٔ 3.10 یا بالاتر
- یک حساب شخصی فعال در روبیکا (با شماره موبایل ایرانی)

## نصب و اجرا (روی سیستم شخصی، برای تست اولیه)

```
pip install -r requirements.txt
```

```
python login.py
```

با اجرای این دستور، شماره موبایل و کد پیامکی روبیکا را وارد می‌کنی و در پایان
یک «رشتهٔ نشست» (Session String) طولانی به تو داده می‌شود.

```
cp .env.example .env
```

فایل `.env` را باز کن و مقدار `RUBIKA_SESSION` را با همان رشته‌ای که از `login.py`
گرفتی پر کن. مقدار `ADMIN_TOKEN` را هم یک رمز دلخواه و قوی برای خودت انتخاب کن.

```
python server.py
```

سپس در مرورگر آدرس زیر را باز کن:

```
http://127.0.0.1:3000
```

## آنلاین کردن پنل (بدون نیاز به روشن بودن کامپیوتر شخصی)

برای این بخش، به فایل `DEPLOY.md` مراجعه کن (راهنمای کامل GitHub + Railway).

## نکات امنیتی

- مقدار `RUBIKA_SESSION` هم‌ارزِ رمز عبور حساب روبیکای توست. هرگز آن را در چت،
  گیت‌هاب عمومی یا جای دیگری به اشتراک نگذار.
- فایل `.env` هرگز نباید commit شود (در `.gitignore` قرار دارد).
- `ADMIN_TOKEN` را طولانی و تصادفی انتخاب کن، چون تنها لایهٔ محافظتی پنل در برابر
  دسترسی غیرمجاز است.

## ساختار پروژه

```
rubika-sender/
├── server.py            # سرور اصلی Flask (معادل server.js)
├── login.py              # اسکریپت ورود و گرفتن SESSION (معادل login.js)
├── session_utils.py      # نگه‌داری session + کلید خصوصی به‌صورت یک رشتهٔ واحد
├── rubika_service.py     # لایهٔ ارتباط با rubpy (افزودن مخاطب + ارسال هوشمند پیام)
├── rate_limiter.py       # سیستم محدودسازی نرخ ارسال (محتاط‌تر از پنل تلگرام)
├── public/index.html     # صفحهٔ پنل (فارسی و راست‌به‌چپ)
├── requirements.txt      # وابستگی‌های پایتون
├── Procfile              # دستور اجرا برای Railway
├── .env.example          # نمونهٔ متغیرهای محیطی
└── data/, uploads/        # ذخیره‌سازی دائمی (state.json، عکس‌ها)
```
